# TLV320AIC3104 firmware module

Status: implemented and tested with a simulated register bus; **not validated on
hardware**. This adds the codec control layer to the STM32H5E5 project. SAI DMA,
audio buffers, effects, USB audio and stream lifecycle are separate future work.
The LED startup/blink application continues to run without accessing the codec.

## Files and build integration

- `firmwaredsp/Core/Inc/tlv320aic3104.h` and `Core/Src/tlv320aic3104.c`:
  portable C11 driver, no HAL or RTOS dependencies.
- `firmwaredsp/Core/Inc/codec_board.h` and `Core/Src/codec_board.c`:
  STM32 HAL transport, I2C1 supplied by caller and PE0 (`SAI_reset`) active-low reset.
- `tests/test_tlv320aic3104.c`: fake register bus, failure injection and readiness timeout.
- `ci/test-codec.sh`: host test runner; Jenkins runs it before CubeMX generation.

The existing CubeIDE Debug/Release source entries include `Core`, and the include
path includes `Core/Inc`; the two new `.c` files therefore belong to both firmware
builds. No generated makefiles or vendor HAL files need modification. CI copies
this project before regeneration. Confirm the build log compiles both new files
when running the target toolchain.

## Linux reference and implementation boundary

The relevant Linux driver is
[`sound/soc/codecs/tlv320aic3x.c`, Linux v6.12](https://github.com/torvalds/linux/blob/v6.12/sound/soc/codecs/tlv320aic3x.c),
not `tlv320aic31xx.c` or `tlv320aic32x4.c`. It explicitly handles the 3104 model.
Reviewed behavior includes PLL bypass, serial format/word length, mute preserving
volume, input/output routing and avoiding registers reserved on the 3104.

Linux's file is GPL-2.0-only. This module is a new implementation from the
[TI SLAS510G datasheet](https://www.ti.com/lit/ds/symlink/tlv320aic3104.pdf)
(also in `AN/tlv320aic3104.pdf`), with Linux as a behavior reference. No Linux source
code or tables are copied. It does not port ALSA, DAPM, Linux regmap, regulator
management, dynamic PLL search, or other AIC3x variants. Register numbers and
bitfields come from the TLV320AIC3104 datasheet. A future literal Linux code port
needs to retain its license and attribution.

## First supported profile

| Setting | Default / supported values |
| --- | --- |
| Control address | Fixed 7-bit `0x18`; HAL receives `0x30` |
| Sample rate | 48 kHz only; unsupported rates rejected before hardware access |
| MCLK | 12.288 MHz (Q=2), or 24.576 MHz (Q=4); codec PLL disabled |
| Clock relationship | `fs(ref) = MCLK / (128 * Q)`; ADC/DAC rate divider = 1 |
| Serial interface | Standard I2S, codec BCLK/WCLK inputs; 16/24/32-bit words |
| STM32 baseline | 24-bit samples in two 32-bit slots; BCLK=3.072 MHz at 48 kHz |
| ADC routes | Left LINE1LP or LINE2L; right LINE1RP or LINE2R, single-ended |
| Default input choice | LINE1 on each channel, to be checked against final schematic |
| ADC PGA | 0 dB; runtime range 0..+59.5 dB in 0.5 dB steps |
| MICBIAS / AGC | Disabled; guitar impedance handled by external input buffer |
| DAC routes | Left/right DAC to corresponding headphone and line outputs |
| DAC level | -12 dB initially; runtime attenuation 0..63.5 dB in 0.5 dB steps |
| DAC startup | Muted until application explicitly unmutes |
| Output common mode | 1.35 V; verify final supply and analog coupling design |
| Headphones | HPLOUT/HPROUT; assumes AC-coupled, ground-referenced headphones |
| COM outputs | HPLCOM/HPRCOM not routed or powered for this profile |
| Output startup | 800 ms driver delay, 2 ms ramp; power-status polling up to 2 s |

This profile must be checked against the completed codec schematic: physical
LINE1/LINE2 connections, analog supply values, coupling capacitors and line-output
connection to LM1875. Differential ADC inputs and capless headphone configurations
are not implemented. Reset disconnects analog bypass routes; all mixing remains
in STM32. DAC digital volume affects both line and headphone output together.
Separate headphone/line volume is not yet exposed.

## Future startup integration

Do not call initialization from the current LED-only main. `HAL_SAI_InitProtocol`
configures the peripheral but does **not** start audio transfers. The future audio
module must supply stable MCLK and continuous BCLK/WCLK, sending zero samples,
before codec initialization. Keep the codec muted until TX/RX streaming is ready.

Example for that future startup path, after HAL/GPIO/I2C setup and SAI clock start:

```c
#include "codec_board.h"

static aic3104_t codec;
aic3104_config_t cfg = aic3104_default_config();
/* Override cfg.left_input/right_input if the final board uses LINE2. */
aic3104_result_t result = codec_board_attach(&codec, &hi2c1);
if (result == AIC3104_OK) {
    result = aic3104_init(&codec, &cfg);
}
/* Check result, then start/verify the complete audio pipeline while muted. */
/* When streaming is ready: result = aic3104_set_dac_mute(&codec, false); */
```

`aic3104_attach` only initializes device memory and binds callbacks. Use it before
first initialization, not to rebind a running device. The HAL handle and callback
context must remain valid. There are no heap allocations. Calls are synchronous;
initialization may wait up to 2 s plus bounded I2C transaction time. Do not call
from a DMA interrupt. Serialize all access to this codec, including page selects;
shared I2C access also needs the application's bus arbitration.

Runtime examples: `aic3104_set_adc_gain(&codec, 0, 0)` sets both ADCs to 0 dB;
`aic3104_set_dac_attenuation(&codec, 24, 24)` sets -12 dB without changing mute;
`aic3104_set_dac_mute(&codec, true)` preserves volume. Check every return value.
Channel updates occur sequentially, not atomically.

Any bus error or readiness timeout asserts hardware reset and clears `ready`.
Even a failure after updating only one channel therefore leaves the codec in
reset, and subsequent controls return `NOT_READY`. Recover the transport/clocks,
then run `aic3104_init` again; this reapplies the whole profile and stays muted.
`aic3104_shutdown` asserts reset without depending on I2C. Invalid arguments do
not change a running codec. Diagnostics read page 0 but do not verify device model:
this part has no driver-supported chip identity check.

## Verification and pending board tests

Run from the repository root:

```sh
bash ci/test-codec.sh
```

Host tests check the clock/format/profile values, input selection, output enables,
gain/attenuation limits, mute preservation, every initialization transaction's
failure path, partial stereo update failure, readiness timeout, and reinitialization.
The mock supplies power-status flags; these tests cannot prove analog performance,
physical I2C timing, supply sequencing or correct audio clock wiring.

First board validation: verify supplies and /RESET; inspect I2C address ACK and
register readback; measure MCLK/BCLK/WCLK; confirm 24-bit TX/RX channel alignment;
check input levels, mute/unmute behavior, headphone startup transient, line output
and recovery after a bus failure. Full CubeMX/CubeIDE build remains a target CI
check; host tests are additional verification, not a replacement.
